## 一、已修复缺陷清单（按严重度排序）

### D8【严重】资金流回退链量纲混杂：同一变量在不同数据源下相差 10000 倍
**位置**：`core/data_engine.py` `_get_capital_flow_big_deal` / `get_tail_end_stats`

- **原因**：`get_main_fund_accumulated` 三源回退链中，源1 ASHareHub 做 `net_mf_amount × 1e4`（万元→元，L1172），源3 同花顺做 亿/万 后缀换算（→元，L1346-1351），唯独源2 大单汇总直接把 akshare `stock_fund_flow_big_deal` 的 `成交额` 列（**单位=万元**，akshare 官方文档明确）加总返回，未换算。
- **影响**：
  1. `calc_main_fund_score` 阈值按元设计（日均 500 万 = 5e6），大单回退路径的值恒打到中性 50 分附近——同一只票走不同回退源得分差可达 30 分；
  2. `skip_asharehub=True` 的配额保护是**日常主路径**（top N 用源1=元、其余用源2=万元），横截面百分位评分被 1e4 量纲差直接污染，排序失真；
  3. 推荐理由文案 `abs(main_fund)/1e4` 把万元值再除 1e4，"300 万"显示成"0 万元"。
- **修复**：大单汇总 net `× 1e4` 统一为元（L1400）；`get_tail_end_stats` 返回的 `total_net`/`tail_net` 同步 ×1e4（`tail_reversal` 符号判断与 `tail_volume_ratio` 比值不受常数缩放影响）。

### D7【严重】VWAP 单位错误：price_position ≈ +9999 恒成立，"强势收尾"信号对所有票误触发
**位置**：`core/data_engine.py` `get_tail_end_stats`

- **原因**：原式 `vwap = Σ成交金额/Σ成交量` = 万元/股 = 真实均价 ÷ 10000（akshare 该接口成交量单位=**股**、成交额单位=**万元**；同花顺实页样例 51.57元×14662股=75.61万元 吻合验证）→ `price_position=(last-vwap)/vwap ≈ +9999`。
- **影响**：`factor_library.py` L582 的 `pp > 0.05 → +6 分`对所有有大单数据的股票恒触发——判别力为零的常数偏置，且造成"有大单缓存 vs 无缓存"股票间的系统性 6 分差距。
- **修复**：改为量加权均价 `Σ(成交价格×成交量)/Σ成交量`（价格列恒为元，**单位无关**，免疫未来数据源口径变化）；实测样例 vwap 从 0.11 → 10.88（真实量加权均价），price_position 从 +9999 → +0.038。

### D1【中】布尔掩码跨 DataFrame 重索引，依赖 pandas 隐式对齐
**位置**：`core/data_engine.py` `get_tail_end_stats` 尾盘买卖分解

- **原因**：`tail_deals[buy_mask & tail_mask]` 中 `buy_mask` 基于 `stock_deals` 全量索引构建，`tail_deals` 是过滤后子集 → pandas 触发 `Boolean Series key will be reindexed` 隐式重对齐；索引重复时直接抛错。
- **影响**：尾盘买/卖金额依赖隐式对齐的正确性；真实 akshare 数据（默认 RangeIndex 拼接）有重复索引风险。
- **修复**：在 `tail_deals` 上直接求性质掩码 `tail_prop`（买=含'买|主'，卖=其余），零重索引、语义完全等价。终验确认无 reindexed 告警、结果与独立参考实现一致。

### D2【中】`iloc[-1]` 顺序假设 + 170 次 ×O(N) 全表扫描
**位置**：`core/data_engine.py` 大单数据加载路径与 `get_tail_end_stats`

- **原因**：① akshare 返回行序不保证，`stock_deals['成交价格'].iloc[-1]` 未必是当日最后一笔成交；② 每次查询都对全市场大单表做布尔扫描（详评 170 只候选 = 170 × O(N)）。
- **影响**：收盘价取错 → price_position 失真；无谓性能开销。
- **修复**：加载时 `sort_values('成交时间', na_position='first')` 固化时序 + `groupby('股票代码').groups` 预建逐股索引；查询端 O(1) 定位（L1451）。合成乱序数据验证 `iloc[-1]` 一定是 14:52 最后一笔。

### D5【中】`np.bool_` 泄漏：JSON 序列化崩溃 + `is` 身份判断失败
**位置**：`core/data_engine.py` `get_tail_end_stats` 返回值

- **原因/影响**：`tail_net > 0 and total_net < 0` 产生 numpy bool 标量——`json.dump` 直接 TypeError；`r['tail_reversal'] is False` 身份判断失败（np.False_ 不是 False 单例）。
- **修复**：`bool()` 强转。终验：`type(...) is bool` 通过、`json.dumps` 全 dict 通过。

### D6【中】numpy 标量泄漏（int64/float64）：JSON 序列化崩溃
**位置**：同上返回 dict

- **原因/影响**：pandas `sum()` 返回 np.int64/np.float64，`json.dumps` 抛 `Object of type int64 is not JSON serializable`；简报/推送落库链路（`eod_stock_picker.py` → 报告 → 小程序推送）全部受威胁。
- **修复**：返回 dict 全字段 `round(float(...))` 强转为 Python 原生标量。

### D3【低】`_assess_market` 北向资金获取失败静默 pass
**位置**：`strategies/short_term.py` 北向流块

- **原因/影响**：`except: pass` 失败不可观测；north=0 默认值使市场评分系统性偏向弱市判定，且与回测评估路径行为不一致（回测/实盘市场状态判断不对等——这是遗留的回测确认阻塞项之一）。
- **修复**：`except Exception as e: logger.warning("北向资金获取失败（市场评估按 0 处理）: ...")`，保留降级语义但留下观测痕迹。

### D4【低】`long_term.py` 数据源状态附加静默 pass
**位置**：`strategies/long_term.py`

- **原因/影响/修复**：同类静默吞错 → warning 日志（截断 60 字符防刷屏）。
