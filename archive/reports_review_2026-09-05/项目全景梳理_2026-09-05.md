# stock-picker-v2 项目全景梳理

> 生成：2026-09-05 ｜ 依据：实际代码结构 + SKILL.md + 近期审查报告，非记忆复述。

## 1. 项目定位与业务目标

- **一句话**：A 股多因子尾盘选股系统 —— 每个交易日尾盘（14:45-14:50）从全市场约 5200 只股票中筛出 1-3 只短线候选，生成简报并推送到微信。
- **明确定位（用户确立）**：**不对接实盘、不自动下单**。系统只做筛选与推荐，买入由用户手动执行；推送内容固定附注"仅供参考，不构成投资建议"。
- **副线能力**：长线持股策略（3-6 个月持有）、历史快照回测、样本外（OOS）因子验证、Ridge 权重优化建议（只报告、人工审批后生效）。
- **本目录性质**：`stock-picker`（原项目基线，保持不动）的**实验副本**，所有优化改动都落在本目录。

## 3. 架构分层与数据流

四层架构（见架构图）：

1. **数据层** `core/data_engine.py`（1968 行）：多数据源统一接入 → 独立熔断 → 配额管理（ASHareHub 100 次/日共享）→ SQLite 缓存 → 失效自动降级。任何一层源挂掉不阻塞整体选股。
2. **策略层** `strategies/short_term.py`（927 行）：市场环境评估（弱市收紧/极差市跳过）→ 预过滤（ST/涨停封死/流动性）→ 初评前 200 → 详评 170 → 7 因子加权评分 → 组合层风控（板块分散 ≤2、连亏降仓 ×0.5、动量硬过滤）→ 专家 ensemble 二次意见 → 仓位分配。
3. **回测/验证层** `core/backtest_engine.py`（1264 行）+ `oos_validator.py`（819 行）：历史快照逐日回放（真实 K 线、滑点分层、T+1 开盘成交惯例），walk-forward OOS IC、三种收益口径、因子相关性/衰减/中性化诊断。
4. **反馈闭环** `feedback/`：推荐入库 → 次日凌晨回填 T+1/T+5 真实收益 → Ridge 优化器只产报告 → `calibrate_weights.py` 按 OOS IC 校准 → **人工审批后**写入 `v1.json` 生效。

**三条主链路**：

- 选股链路：`eod_stock_picker.py --mode short` → ShortTermStrategy.run() → DataEngine 取数 → factor_library 算因子 → ScoringModel 打分（v1.json 权重）→ PortfolioOptimizer 仓位 → 简报落盘（`data/reports/short_YYYYMMDD(_briefing).md`）→ predictions.db 落库（当日防重）→ 推送。
- 回测链路：`run_backtest.py` → BacktestEngine 逐日历史快照 → 模拟成交/仓位 → backtest_store 版本化落库 → `--mode oos` 走 oos_validator。
- 反馈链路：`backfill_pending.py`（凌晨 3:15 回填收益）→ optimizer.check_and_report（仅报告）→ `calibrate_weights.py` → 审批 → v1.json。

## 7. 技术债务与改进点（按重要性）

1. **回测/实盘评估环境不均等**（遗留决策）：回测中 hot_count=0、north=0 系统性压低市场评分 → 42/45 天判"极差市"跳过，导致动量过滤的策略级回测确认被阻塞。这是当前最值得修的方法学问题。
2. **模型结论**：评估结论为"未达稳定盈利标准"但具备正期望结构（run23 t=1.74 不显著、3/8 个月为正）；需持续积累面板后复验。
3. **SKILL.md 滞后**：因子权重表仍是旧值（25/25/15...），路径写的还是原项目 `stock-picker`；文档与代码不同步违反其自身规范。
4. **data_engine.py 上帝模块**（1968 行）：数据源、熔断、配额、缓存混在一起，建议按源拆分 provider。
5. **根目录堆积 13 个 `_verify_*.py`** 临时验证脚本，应归档到 tests/ 或删除。
6. **数据冗余**：`data/db` 与 `data/cache` 各有一份 kline_cache.db，另有 `data/_legacy/`；需确认唯一真源并清理。
7. **mootdx 解析怪癖**：个别退市/停牌票报 `month must be in 1..12`（有降级，不阻塞）。
8. **节假日日历缺失**：定时任务周末/节假日会照跑（脚本防重+如实报告，影响有限）。
9. **ASHareHub 单点**：配额 100/日、key 依赖环境变量（已写用户级变量+提示词兜底）；4/5 数据面可被免费源替代，长期可降级为增强源。
10. **ROI 计划遗留项**：#3 全市场资金流回填、#7 风格因子批量池、#9 退市股宇宙、#10 面板 Ridge、#11 LightGBM（需 60+ 天面板）。
