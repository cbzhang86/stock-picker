- 审查日期：2026-09-05

- 审查方式：全量代码走读（core/strategies/scripts/feedback 约 1.2 万行）+ 实际证据文件核对（`data/reports/oos_ic_*.json`、`weight_calibration_20260905.md`、`data/weights/v1.json`）

## 0. 总体结论

**工程质量明显高于同类个人/小团队项目，但策略层存在若干"沉默失效"点，当前回测成绩的可信度被打折扣。**

- **做得好的（行业少见）**：样本外验证器（逐日横截面 IC + walk-forward + 三收益口径 + 悲观证据聚合 + 等权先验收缩 λ）设计接近小型私募水准；数据工程（独立熔断、配额账本原子写、NaN 清洗、源状态登记）扎实；文档纪律（陷阱登记 1–22、改动三步走）优秀；权重校准器对"研报中位数权重被实测推翻"的响应方式科学。
- **核心风险**：系统存在 **4 个 P0 级"代码意图与实际行为不符"问题**（Ensemble 空转、涨停过滤死代码、权重双源失同步、卖出规则未进回测），以及回测/实盘因子口径漂移。**在修复这些问题之前，任何回测成绩（包括 +51.29%、夏普 4.36）都不应作为权重或参数决策的依据。**

## 1. P0 发现：代码意图 ≠ 实际行为（必须先修）

### P0-1 ExpertEnsemble 完全空转（严重度：高）
- **位置**：`strategies/short_term.py` L249–265；`core/expert_ensemble.py` 各维度函数。
- **表现**：Ensemble 的 `src_for_ensemble` 从**瘦 rec dict** 取 `fundamentals / recent_events / main_fund_accumulated / rps / pe_percentile / pb_percentile / volume_ratio` 等字段——这些字段只存在于 `rec['_src']`（全字段源 dict），从未复制到 rec。结果五个维度全部收到 `None`，**专家分恒等于 50.0**。
- **连锁后果**：`min_score=75` 时所有推荐 score≥75，`Δ = 50 − score ≤ −25`，**每一条推荐都触发"高度分歧 conflict"告警与 ×0.5 降仓系数**——日志全是误导性噪音；融合分 `ensemble = 0.85×score − 0.5` 是 score 的单调变换，归一化后**仓位分配数学上与不融合完全相同**。
- **影响**："5 维专家第二意见"这个 V4.2 主打特性实际贡献为零，还污染日志、给运维人员错误信号。
- **修法**：`src_for_ensemble = rec.get('_src', rec)` 一行改动即可让真实数据进入五维；修完后需重新验证 confidence 分档与仓位系数的实际效果。

### P0-2 涨停封死过滤是死代码（严重度：高）
- **位置**：`core/risk_filter.py` L116–122（`limit_up_amount` 判定）；全仓库 grep 确认**没有任何数据源填充该字段**（仅 docstring 与读取处出现）。
- **表现**：`exclude_limit_up: true` 在**实盘与回测中同样无效**——条件 `pct_chg≥阈值 AND limit_up>0` 永远为假。收盘涨停的股票照样进入推荐池。
- **影响**：尾盘策略买入"当日已涨停"的票是典型的打板接力行为，风险特征与策略设计初衷完全不同；回测里这类样本（次日高开低走概率高）会系统性扭曲收益统计。
- **修法**：无封单数据时改用代理规则——`pct_chg ≥ 板块上限×0.98` 直接硬过滤；腾讯行情若可取买一封单量则补真字段。

### P0-3 权重存在三个互相矛盾的"事实源"（严重度：高）
- **位置**：`config.yml` short_term.weights（capital_flow 0.3036 / hot_theme 0.50 / …）≠ `data/weights/v1.json`（capital_flow 0.15 / technical 0.16 / volume_price 0.12 / momentum 0.04 / …）≠ `SKILL.md` 与 `short_term.py describe()` 文档（25/25/15/10/10/10/5 旧权重）。
- **表现**：实际生效的是 v1.json（加载优先级最高，陷阱 21 自己都写明了，但三处仍然漂移）。两套"2026-09-05 校准"数字并存，无法追溯哪套是最终审批结果。
- **影响**：回测复现、审计追溯、后续校准（calibrate_weights.py 读 v1.json 作"当前权重"）全部建立在不可靠基线上。
- **修法**：确立 v1.json 为唯一事实源；config.yml 权重段注释降级为"历史记录（不生效）"；文档同步；在 `verify.py` 增加一处一致性巡检。

### P0-4 卖出规则从未进入回测（严重度：高）
- **位置**：`core/backtest_engine.py` `_calculate_results` / `_simulate_portfolio`（一律 T+1 收盘卖）；`config.yml sell` 段（止盈 +2% / 止损 −2% / 时间止损 T+3）。
- **表现**：止盈、止损、时间止损三个规则在回测里完全没有被模拟。T+5 收益计算甚至不扣成本（L538）。回测度量的是"无条件持有 1 天"的收益，与策略真实持仓行为不是同一个策略。
- **影响**：止损 2% 对热点小盘股（日内振幅 5–8%）会被日常噪音频繁触发，真实胜率/收益分布可能与回测完全不同；策略宣称的风险控制未经任何验证。
- **修法**：在组合模拟中加入盘中 touch 逻辑（用 high/low 判定先触止盈还是止损，同日同时触及按保守假设），并支持 T+3 时间止损路径。

## 2. 分维度审查与行业对照

### 2.1 因子构建与有效性

**现状**：10 个因子（capital_flow / momentum / technical / volume_price / hot_theme / dragon_tiger / north_flow / valuation_fundamental / event_catalyst + risk 过滤层）。K 线类因子向量化实现规范；资金流用横截面百分位、动量用 RPS 排位，符合行业做法。

**OOS 实测证据**（2026-06-30~09-03，47 交易日 / 889 只 / 36892 行，`oos_ic_..._hold1d.json`）：

| 因子 | 测试集 IC | walk-forward 均值 | 稳定性 | 现权重(v1.json) | 判定 |
|---|---|---|---|---|---|
| hot_theme | +0.0472 | +0.0651 | 3 折全正 | **50%** | 有效（唯一） |
| capital_flow | +0.0045 | +0.0056 | 不稳定 | 15% | 噪声（覆盖率仅 10.5%） |
| dragon_tiger | +0.0040 | −0.0072 | 不稳定 | 3% | 噪声 |
| volume_price | −0.0562 | −0.0460 | 3 折全负 | 12% | **稳定反向** |
| technical | −0.0673 | −0.0462 | 不稳定 | 16% | 反向 |
| momentum | −0.1254 | −0.0926 | 不稳定 | 4% | **强反向** |

**与行业实践的差距**：

| 环节 | 本项目 | 行业主流 | 差距与影响 |
|---|---|---|---|
| 因子标准化 | 绝对值分段映射（量比锚点、换手分带）直接打 0–100 分，仅资金流/动量用百分位 | MAD 去极值 → 横截面 z-score/rank → 中性化 | 绝对阈值跨市场状态漂移（牛市量比中枢整体上移后映射失真）；中性化工具（`neutralized_ic`）已建成但**未接入生产因子** |
| 因子有效性检验 | 逐日 IC + walk-forward + 三口径 + IC 衰减 + 相关性矩阵，47 天样本 | 同类方法 + **1–3 年滚动窗口** + 分组收益（quantile spread）+ 多重检验校正 | 方法论已达标，**样本量差一个数量级**；无 DSR/PBO；只报 IC 未报多空分组收益，无法评估可交易性 |
| 因子口径一致性 | **三套定义并存**：volume_ratio 实盘=腾讯分钟折算量比 / 回测=20日均量（backtest_engine L232）/ OOS 面板=5日均量（oos_validator L229）；volume_price 尾盘加成（±30 分）仅实盘存在；turnover 回测恒 0、pe/pb 回测恒 None | 单一因子定义函数全链路复用 + 因子版本哈希落库 | "验证的因子"和"实盘跑的因子"不是同一个因子，IC 结论对实盘的代表性打折；回测预筛排序与实盘系统性不同（turnover/PE 恒定值导致预筛分恒定项） |
| hot_theme 生产公式 | OOS 只验证了 is_hot 二值（70/50）；生产公式还含板块涨幅加权、龙头加成、**概念数量计数（≥10 个概念 +15 分）** | 每个加法成分独立验证 | 50% 的权重押在一个**部分成分未经验证**的复合因子上；概念计数加分实质是"题材蹭热度"代理，极可能是小盘炒作票的代理变量，方向未证 |
| 新因子启用路径 | config 注释：积累 60 天快照后跑 `--mode oos` | — | **流程断裂**：`oos_validator.ALL_FACTORS` 不含 valuation_fundamental/event_catalyst，计划中的验证工具尚不支持这两个因子 |

### 2.2 权重分配方法

**现状**：`calibrate_weights.py` 按主口径 IC × 口径一致性折扣 × 可靠性折扣生成 IC 权重，λ=0.25 向等权先验收缩，负 IC 指数惩罚，单因子 50% 上限。方法论（先验收缩、可靠性门控、坍缩保护）**优于行业常见的纯 IC 加权**。

**差距与影响**：

1. **输入证据太薄**：λ 只有 0.25（测试集 ~14 天），却已把 50% 权重给到 hot_theme。上限截断后额度回流产生过"dragon_tiger 负 IC 拿 10.6%"的副作用（校准报告自己已标记）。
2. **忽略因子相关性**：`factor_corr()` 工具已实现但没进权重计算。hot_theme 50% + capital_flow 15% 均为"热点/资金"类，若相关性高，有效分散远低于表面。行业做法：ICIR 加权前先正交化，或均值-方差聚合。
3. **覆盖率无闸门**：capital_flow 覆盖率 10.5%（回测口径缺历史）仍拿 15% 权重，校准报告已警告。行业惯例：覆盖不足的因子权重封顶或剔除。
4. **无再校准节奏**：λ 会随样本自动放开（设计正确），但没有规定"每月重跑 / 覆盖≥60 天才允许 λ>0.5"之类的触发规则。
5. **治理缺陷**：见 P0-3，双事实源使"当前权重"这个校准输入本身不可靠。

### 2.3 模型结构

**现状**：线性加权评分（7 因子）→ 5 维专家 Ensemble 融合 → Ridge 反馈优化器（刻意停用）。评级映射 5 档。

**与行业主流（线性 → GBDT/NN 排序模型 + purged CV）的对比与判断**：

| 项 | 评价 |
|---|---|
| 线性加权主模型 | 对日线频、低样本、强可解释性需求的个人系统是**合理选择**，不必盲目上 ML。但输入侧的绝对值分段映射压缩了信息——先做横截面标准化，线性模型的表达力会明显提升 |
| ExpertEnsemble | 融合公式（0.15×Δ + 常数加成 − 冲突惩罚）是拍脑袋参数，且当前完全空转（P0-1）。**在拿到"ensemble 相对纯模型有增量 IC"的证据前，不建议启用**；行业做 stacking 需要两层交叉验证拟合融合权重 |
| Ridge 反馈优化器 | 停用是**正确的**（其训练集是"被推荐出来的票"，选择偏差严重、因子方差被 min_score 压缩）。若未来启用，必须在**全横截面**上回归而非推荐样本上 |
| 防凑数裁剪（第 3 名与第 1 名分差 >20 分砍尾） | 行业少见的好细节 |
| 评级/目标价 | 长线 +15%/−8% 硬编码，与 config 无联动；小瑕疵 |

### 2.4 整体策略思路（市场择时 + 组合构建）

**做得对的**：市场环境评估（涨跌比/涨跌停比/中位数涨幅/强势股数/北向，零 API 成本）→ 极差市全停、弱市半仓；同板块 ≤2 只分散；连亏 3 日降仓；20cm/30cm 板涨跌幅上限修正（P2-4）——这套"择时 + 组合层风控"框架在散户系统里属于高配。

**差距与影响**：

1. **市场评估的 hot_score 在回测中恒为 0**（回测无热点数据，L499 `hot_count=0` → 0 分），而实盘常在 50–100 分。**回测的市场分比实盘系统性低约 7.5–15 分** → 回测更频繁地判"弱市/极差市"并跳过/半仓，回测的择时行为与实盘不可比。
2. **固定 2% 止盈止损**：不随波动率缩放。热点小盘股日均振幅 5–8%，2% 止损会被噪音打穿；行业用 1×ATR 或 k×σ 自适应。且止损-止盈 1:1 对称 + 胜率 53.85% 的组合，盈亏比约 1:1，**扣完成本后期望收益对胜率的依赖极高**，胜率下滑 3 个点就可能由正转负。
3. **无策略级 kill-switch**：只有"连亏 3 日降仓"，没有"月内回撤 >X% 停推"的硬闸。
4. **仓位分配**：评分加权 + 单票上限 40% + 下限 10%，属朴素做法；无波动率倒数加权、无相关性别约束（同板块约束是代理）。行业对 3 只票的组合通常做等权或波动率平价起步——**评分加权在 3 只票上差异其实很小**，反而引入"高分票集中度"风险。
5. **基准错配**：策略实际持仓是热点/题材小盘风格，用沪深 300 做超额基准，超额收益数字天然偏乐观。应至少并行报告中证 1000 / 中证全指。

### 2.5 数据处理（主动检查项）

**做得好的**：6+ 数据源、独立熔断与状态登记、ASHareHub 配额账本（原子写+线程锁+跨进程）、分级配额（top10/15/20 分档消耗）、NaN/Inf 清洗双保险（sanitize_nan + allow_nan=False）、K 线 SQLite WAL 缓存、复权口径有专门验证脚本（_verify_qfq.py）。

**差距与影响**：

| 问题 | 表现 | 影响 |
|---|---|---|
| 历史深度不足 | K 线缓存 4483 只 / 2025-06~2026-06（1 年）；因子快照（资金流/热点）仅覆盖近 47 天且只记录候选池（覆盖率 10%） | OOS 验证窗口被数据卡死；capital_flow——权重 15% 的因子——的有效性基本**未经验证** |
| 幸存者偏差 | 股票池=今日代码列表；股票名取自今日行情（历史 ST 状态不可见） | 回测收益略偏乐观；行业用含退市股的时点成分股 |
| 基本面无时点 | `FundamentalProvider.get_many` 无 as_of；回测把**今天的估值/财务**挂到历史日期（事件有 as_of、基本面没有） | 当前权重 0 无实害；一旦按计划启用 valuation_fundamental 并回测，就是前视泄漏 |
| 数据源单一依赖风险 | 行情=腾讯、K线=mootdx，单点故障有熔断但无第二行情源交叉校验价格 | 极端情况脏价直接进评分（有双源校验的仅 technical） |

### 2.6 回测框架（主动检查项）

**做得好的**：真实 K 线逐日回放（无 np.random）、回测日期 K 线截断防前视（bt_start=回测日−120 天）、分层滑点接口、close_t0/open_t1 双成交口径、基准拉取失败标记 benchmark_available、月度归因错配修复（P2-1）、快照透传修复让 capital_flow 真正进回测。

**差距与影响**（按严重度排序）：

1. **卖出规则未模拟**（P0-4）——策略行为与回测度量不一致。
2. **逐笔收益当逐日收益算 Sharpe**：`_calculate_results` 把每笔 T+1 收益 i.i.d. 复利并 ×√252 年化，隐含"每笔全仓、日日满仓"；`_simulate_portfolio` 只统计有交易的日、当日资金归一化全投、弱市半仓不进回测。**夏普 4.36 与策略收益 +51.29%/62.50% 均为口径虚高值**，行业可比口径下预计显著缩水。
3. **涨停过滤失效**（P0-2）在回测中让"涨停次日接力"样本混入。
4. **候选池代表性**：OOS 面板 889 只 vs 全市场 ~5000；回测预筛的 turnover/PE 恒定项使候选池排序与实盘不同。
5. **无多重检验意识**：min_score 60→75、动量过滤开关、多版权重，同一区间反复试验挑优，无 DSR/PBO 校正——当前最好成绩有相当概率是试验族里的幸运样本。
6. 细节：T+5 收益不扣成本；交易日历降级用"周一到周五"（节假日会跑空日）；`_load_factor_data` 连接无 try/finally（已知遗留）。

### 2.7 风险控制（主动检查项）

**已有**：ST/退市过滤、跌停拦截、解禁 90 天 ≥50% 硬拦、成交额/换手/量比异常软惩罚、市场环境三档、板块分散、连亏降仓、北向停公开处理。

**差距与影响**：

| 缺口 | 表现 | 影响 |
|---|---|---|
| 止损非波动自适应 | 固定 ±2%，热点票日内噪音即可触发 | 频繁止损磨损 + 亏损分布左尾未被真正控制 |
| 跳空/流动性风险未建模 | 回测假设 T+1 收盘可按市价卖出；跌停开盘卖不出的情形不存在于模拟 | 极端日真实亏损 > 回测最大回撤 |
| 无组合波动控制 | 仓位只看评分与板块，不看个股波动率与组合相关性 | 同涨同跌日（题材联动）单日回撤放大 |
| 涨停过滤死代码 | 见 P0-2 | 接力板风险敞口 |
| 时间止损未验证 | T+3 时间止损规则存在但从未被回测检验 | 规则有效性未知 |

### 2.8 交易成本（主动检查项）

| 成本项 | 现状 | 行业应有 |
|---|---|---|
| 佣金 | 万三 × 买卖双边 ✅ | ✅ |
| **印花税** | **缺失**（卖出 0.05%，2023-08 后税率） | 必含 |
| 过户费 | 缺失（0.001% 双边） | 应含 |
| 滑点 | 固定 0.1%；分层滑点**接口已实现但 config 未启用** | 按成交额/参与率分层，最好挂钩当日成交量 |
| 冲击成本 | 无（未按"下单金额/当日成交额"参与率建模） | 单票 40% 仓位 × 小额成交票时不可忽略 |

**影响量化**：真实往返成本 ≈ 万三×2 + 印花 5 + 过户 0.1 + 滑点 10×2 ≈ **0.31%**（现回测只算 0.26%）。以 +2% 止盈为目标，成本占毛收益 **~15%**；每笔收益被系统性高估约 5bp，年化 50 笔即 ~2.5 个百分点。

## 4. 优先级路线总结

```
第一步（本周）：P0-A/B/C/D/E —— 修正确性。修完重跑一次基线回测，
               该数字才是第一个可引用的成绩。
第二步（2-4周）：P1-F/G/H —— 扩样本重验证 + hot_theme 拆分验证。
               若 hot_theme 拆分后 IC 保持 ≥0.04，50% 权重可保留；
               否则降到 30% 并把额度还给 capital_flow（待其覆盖≥60天再评估）。
第三步（1-2月）：P2-K/L/N —— 标准化 + 相关性感知权重 + 波动率风控，
               然后才考虑 M（ML 影子基线）。
全程：P3 监控兜底。
```

**核心判断**：这套系统的"验证方法论"已经领先于多数同类项目，当前的主要矛盾不是"缺新因子/缺模型"，而是**已建成的验证体系与生产代码之间的口径断裂**（P0 五项 + 因子三口径）。把断裂接上之后，现有方法论足以支撑下一阶段的权重演化；在那之前新增任何因子或调任何权重都是在流沙上盖楼。
